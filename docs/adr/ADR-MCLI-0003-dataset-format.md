# ADR-MCLI-0003: Dataset derived from the pages

**ADR ID**: ADR-MCLI-0003
**Status**: accepted
**Date**: 2026-11-19
**Author**: jasagiri (drafted by Claude Opus 5.5)

## Context

The same knowledge is wanted as fine-tuning data. nim-cs-knowledge derives its dataset mechanically
from tested sources (ADR-NCK-0003); this repository has pages and run examples instead of modules.

## Requirements

- Every command in an answer is a command the tests ran, with the output they compared.
- Regenerating from unchanged pages changes no byte.
- Each record names its page and block line, so a bad record is fixed at its source.
- Records teach when not to switch, not only how to switch.

## Options

1. **Hand-written JSONL.** A second copy of every fact.
2. **Generated by an LLM** from the pages. Varied; untested and not reproducible.
3. **Derived mechanically** from the pages by `tools/dataset_build.nim`.

## Trade-offs

Option 3 has template phrasing, but every answer is tested and traceable, as in nim-cs-knowledge.

## Decision

Option 3. `dataset/records.jsonl` and `dataset/chat.jsonl`, sorted by id, with the fields of
ADR-NCK-0003 (`id`, `kind`, `area`, `concept`, `instruction`, `input`, `output`, `specIds`,
`sources`, `files`), `area` = `cli` and `concept` = the page name. Kinds:

- `explain`: the page's Intent and Differences that change results.
- `task`: instruction from the prose line before a verified ```sh block; output the command and
  its compared output.
- `rewrite`: input the ```sh classic command; output the modern command, the shared output and the
  page's differences.
- `pitfall`: input the ```sh bad block; output the fix and its output.
- `keep-classic`: the page's When to keep the classic command section.

Nothing comes from a page marked 未検証 or from a ```sh unverified block (MCLI-DATA-02).

## Not decided here

- Train/validation splits.

## Rejected alternatives

Options 1 and 2 above.
